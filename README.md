# Свои · Telegram Mini App

Сервис для заведений и их гостей: вход через Telegram, общая серверная база, персональные бонусы, визиты, отзывы и внутренние заметки команды. Один Telegram-аккаунт получает один профиль, доступный с разных телефонов. Интерфейс React Native Web / TypeScript собирается Expo для Telegram WebView на iOS и Android.

Исходники доступны публично для ознакомления; собственный код не предоставлен под открытой лицензией. Условия — [LICENSE](LICENSE), уведомления сторонних компонентов — [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Для разработки см. [CONTRIBUTING.md](CONTRIBUTING.md), для безопасной работы — [SECURITY.md](SECURITY.md). [Состояние продукта](docs/PRODUCT_STATUS.md) отделяет готовые функции от условий первого рабочего пилота.

## Заведения для гостя

После входа гость сначала видит карточки опубликованных заведений и своих клубов. Выбор открывает отдельную страницу с условиями и доступными действиями; возвращение в каталог и повторный вход не выбирают заведение автоматически. Просмотр не создаёт членство или визит.

В панели разработчика раздел «Карточка для гостей» управляет публикацией, тестовым статусом, оформлением, описанием, особенностями, условиями и HTTPS-ссылками. Бонусы, визиты и отзывы включаются отдельно для каждого заведения. Ограничения проверяет сервер, включая кассовые начисления; прежняя история и остатки сохраняются.

«Эль Пастор» подготовлен как тестовая карточка: бордовая палитра заведения, чёткая типографическая адаптация названия, тонкий орнамент, плавный световой блик, ссылки на бронь и афишу. Маленький растровый аватар не используется для крупной надписи. Локально встроен Cormorant Garamond Bold (OFL); анимация отключается при prefers-reduced-motion. Условия участия не согласованы; бонусы, учёт визитов и отзывы выключены. Источники оформления: assets/venues/elpastor.source.json; сведения о шрифте: assets/fonts/SOURCE.md.

Внутренняя страница «Эль Пастора» оформлена как клубная карта: тёмное бордо, кремовый текст, золотистые кнопки и персональный блок гостя. Её экран QR использует ту же палитру, но сам код остаётся статичным чёрно-белым с защитным белым полем. Это тот же личный QR «Своих», а не новый код или подтверждение участия в клубе. Шапка Telegram получает цвет заведения на поддерживаемых клиентах; при возвращении в каталог восстанавливается общий стиль. На ширинах 320/390 px QR независимо распознан из скриншота; физическая камера телефона этим не проверяется.

## Начало работы

1. Откройте [бота «Свои»](https://t.me/svoi_guestclub_demo_bot), отправьте `/start` и нажмите «Открыть “Свои”».
2. При первом входе создаётся пустой личный профиль. Вымышленные гости, чеки и балансы старого демо не переносятся в общую базу.
3. Разработчик «Своих» добавляет заведение в закрытой панели и выдаёт одноразовый код руководителю. Самостоятельной регистрации владельцев нет.
4. Руководитель принимает код через «Я сотрудник», затем выдаёт сотрудникам собственные одноразовые приглашения на 24 часа. Код клуба для гостей не даёт прав сотрудника или руководителя.
5. Гость показывает личный QR. Сотрудник сканирует его в выбранном заведении и видит карточку: предпочтения, число визитов, последнее посещение и баланс. Затем выбирает нужное действие. Само сканирование не создаёт визит и не начисляет бонусы. Без камеры можно ввести личный код гостя.
6. После подтверждения визит и бонусы видны на телефоне гостя. После визита можно оставить отзыв, команда может ответить.

Коды приглашений можно скопировать кнопкой; если Telegram запрещает буфер обмена, код остаётся доступным для выделения. Закрытие доступа сотруднику требует подтверждения. Суммы чека и чаевых проверяются до отправки; пустые чаевые означают 0.

У сотрудника три раздела: «Смена», «Гости» и «Ещё». Основное действие — QR; ручные начисления и комплименты находятся внутри карточки гостя. Руководитель в настройках выбирает кассовую систему заведения. Для iiko карточка предлагает продолжить обслуживание в iikoWaiter: по проверенной HTTPS-ссылке интегратора, если она настроена для телефона, иначе показывает инструкцию ручного перехода. Ссылки установки приложения обозначены отдельно. Передача гостя, стола и заказа в Waiter пока не подключена; открытие ссылки не подтверждает запуск приложения. При кассовом импорте не дублируйте тот же чек ручным визитом.

При потере связи показываются последние загруженные данные и время их обновления. Уже загруженный личный QR остаётся видимым. После возвращения интернета приложение запрашивает актуальные данные; новые визиты и начисления требуют успешного ответа сервера.

Обычная ссылка в браузере показывает вход и переход в Telegram. Данные `initDataUnsafe`, имя пользователя и код гостя сами по себе не являются способом входа. Сервер проверяет подписанную Telegram строку `initData` и её срок действия.

## Доступ и данные

- Гость получает только свои визиты, бонусные операции и отзывы. Внутренние заметки и оценки команды не передаются гостевому аккаунту.
- Сотрудник получает доступ только к назначенным ему заведениям. Руководитель настраивает программу и управляет командой; отзыв прав проверяется сервером при следующем запросе.
- Панель разработчика доступна только Telegram ID из серверного `DEVELOPER_TELEGRAM_IDS`. Она показывает заведения и руководителей; роль разработчика сама по себе не открывает историю гостей чужих заведений. Список по умолчанию пуст, первый вошедший пользователь не становится администратором.
- У каждого гостя устойчивый случайный QR без имени, телефона и Telegram ID. Это идентификатор для команды, а не пароль и не способ входа. Сканирование доступно только сотрудникам своего заведения и не создаёт визит до отдельного подтверждения.
- Смена вида интерфейса не выдаёт права. Telegram ID, роли, суммы начислений и остатки проверяет сервер.
- Все изменения проходят через серверные команды. Визит, расчёт бонусов и запись операции сохраняются атомарно; повтор запроса с тем же ключом не дублирует начисление или списание.
- Ключи неподтверждённых операций сохраняются в `sessionStorage` без токена и содержимого команды. Повтор после потери ответа, закрытия формы или перезагрузки использует прежний ключ. Если браузер не даёт сохранить ключ, новая операция блокируется до отправки.
- Комплимент за бонусы оформляет сотрудник с проверкой остатка. Гость не может самостоятельно уменьшить баланс и выдать себе подарок.
- Синхронизация выполняется периодическим обновлением и при возвращении в приложение. При недоступном сервере изменение не считается сохранённым.
- Сессия действует до 12 часов; клиент держит её токен в памяти. После закрытия Mini App вход повторяется через Telegram. В базе хранится хеш токена сессии.
- При смене версии сайта серверная история сохраняется. Очистка данных браузера не удаляет серверную историю.

Программы заведений независимы: кешбэк, бонус за каждый N-й визит, благодарность за чаевые и ручное начисление с причиной. Профили создаются без номера телефона. Личный код гостя позволяет команде найти и присоединить профиль, но не войти от его имени.

## Кассовые интеграции

Для каждого заведения подготовлены серверные подключения iikoCloud и r_keeper White Server: защищённые ключи, проверка доступа, очередь чеков, привязка гостя, автоматические начисления и журнал обмена. **Реальных подключений пока нет: доступы заведений ещё не предоставлены.** Руководитель сможет настроить своё подключение в приложении; перед рабочим запуском требуется сверка на кассе. Возвраты отправляются на ручную сверку, автоматического сторнирования пока нет. Симуляторы доступны отдельно и не меняют общую базу. Требования и ограничения — [INTEGRATIONS.md](INTEGRATIONS.md).

## Локальная разработка

Нужен Node.js 22.22 или новее. SQLite входит в Node.js; отдельный сервер базы не нужен.

```powershell
npm ci
npm run build
npm start
```

Настройки возьмите из `.env.example` и сохраните в непубликуемый `.env.local`. Настоящий токен бота нельзя помещать в клиентский код, Git, архивы или переписку. `DATABASE_PATH` задаёт постоянный файл базы вне папки релиза; локально — `./data/svoi.sqlite`, на VPS — `/var/lib/svoi/svoi.sqlite`.

Для реального входа Mini App открывается через бота на публичном HTTPS-адресе. Без валидных данных Telegram локальный сайт показывает экран входа. Тесты используют отдельные базы и тестовые подписи; в опубликованном приложении нет обхода авторизации для разработки.

После изменений интерфейса выполняйте `npm run build`: сборка добавляет официальный Telegram SDK и генерирует серверную версию общего модуля расчётов. Для работы сайта нужны и `dist/`, и `server/`; статического хостинга недостаточно.

## Бот и сервер

Бот поддерживает `/start`, `/help`, `/privacy`, меню и кнопку Mini App. Он отвечает на входящие сообщения в личном чате, рассылок нет. При существующем webhook процесс останавливается, не удаляя чужую настройку. Используется отдельный бот проекта; перед изменением меню, описания и команд процесс сверяет `getMe` с `EXPECTED_BOT_USERNAME` (по умолчанию `svoi_guestclub_demo_bot`). При несовпадении запуск прекращается.

Сайт и бот запускаются отдельными процессами. API проверяет доступ на каждом запросе; SQLite хранит учётные записи, права, операции и журнал действий. Инструкции по размещению и резервным копиям — [deploy/README.md](deploy/README.md). Сведения об инфраструктуре — [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:ui
```

Серверные проверки должны покрывать поддельные и просроченные данные Telegram, изоляцию гостей и заведений, приглашения и отзыв доступа, повторы запросов, списания и сохранение после перезапуска. Браузерные тесты не заменяют проверку на настоящих телефонах внутри Telegram.

Проект рассчитан на первый пилот на одном VPS. Независимого внешнего хранилища резервных копий и оценки большой нагрузки пока нет. Старые демоданные остаются только в прежнем локальном хранилище устройства и не влияют на рабочие балансы.

Официальные материалы: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Bot API](https://core.telegram.org/bots/api), [Expo SDK 58](https://docs.expo.dev/versions/v58.0.0/), [Node.js SQLite](https://nodejs.org/docs/latest-v22.x/api/sqlite.html).
