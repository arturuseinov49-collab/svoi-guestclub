# Размещение и сохранность данных

Приложение использует один Node.js-процесс API со встроенной SQLite и отдельный процесс Telegram-бота. Сборка выполняется локально. Начальная конфигурация VPS — 1 ядро, 1 ГБ RAM, 20 ГБ диска; реальная предельная нагрузка ещё не измерена.

## Структура сервера

- `/opt/svoi/releases/ВЕРСИЯ` — код релизов, без рабочих данных и секретов.
- `/opt/svoi/current` — ссылка на активный релиз.
- `/etc/svoi/svoi.env` — конфигурация, доступная root, права `0600`.
- `/var/lib/svoi/svoi.sqlite` — общая база. Файлы `-wal` и `-shm` рядом с ней принадлежат SQLite; их нельзя удалять во время работы.
- `/var/lib/svoi/data/bot-offset.json` — позиция polling бота.
- `/var/lib/svoi/backups/` — место резервных копий на этом же VPS.

Пользователь процессов — `svoi`, без root. Для веб-сервиса нужен `ReadWritePaths=/var/lib/svoi` при `ProtectSystem=strict`, иначе SQLite не сможет сохранять данные. Каталог данных — `0750`; файлы базы и копий не должны быть доступны веб-серверу как статические файлы.

## Установка и обновление

Нужен Node.js **22.22 или новее**. В архив входят `dist`, `server`, `bot`, `deploy`. Не включайте токены, SQLite, резервные копии, `node_modules` или данные локальных тестов. Серверный `domain.mjs` генерируется сборкой и должен быть в архиве.

Перед установкой проверьте существующие сервисы и порты 80/443/8081. Не переустанавливайте ОС и не останавливайте приложения других проектов.

```bash
mkdir -p /opt/svoi/releases/RELEASE_ID
tar -xzf /root/svoi-deploy.tar.gz -C /opt/svoi/releases/RELEASE_ID
bash /opt/svoi/releases/RELEASE_ID/deploy/install.sh YOUR_PUBLIC_DOMAIN /opt/svoi/releases/RELEASE_ID
```

В `/etc/svoi/svoi.env` задаются:

```text
HOST=127.0.0.1
PORT=8081
PUBLIC_APP_URL=https://YOUR_PUBLIC_DOMAIN
DATABASE_PATH=/var/lib/svoi/svoi.sqlite
TELEGRAM_BOT_TOKEN=секретный_токен
EXPECTED_BOT_USERNAME=svoi_guestclub_demo_bot
DEVELOPER_TELEGRAM_IDS=подтверждённый_числовой_Telegram_ID
```

Скрипт установки создаёт системного пользователя и сервисы, настраивает Caddy, сохраняя другие приложения. Бот запускается после заполнения токена. Не выводите файл окружения в логи и не публикуйте его содержимое.

`DEVELOPER_TELEGRAM_IDS` — закрытый список числовых Telegram ID через запятую. Назначайте только проверенные аккаунты администратора платформы. Username не используется для постоянных прав: он может измениться. Пустая настройка закрывает создание заведений и назначение руководителей всем пользователям. Панель не выдаёт права разработчика из интерфейса. При обновлении существующие роли `owner` сохраняются как руководители заведений; SQLite добавляет QR каждому аккаунту и тип приглашения, сохраняя историю и балансы.

При обновлении сначала создайте согласованную резервную копию базы, распакуйте новый релиз в отдельную папку, затем переключите `/opt/svoi/current` и перезапустите только `svoi-web`/`svoi-bot`. Файл базы остаётся в `/var/lib/svoi`, поэтому переключение кода не удаляет историю. Откат кода не является откатом данных; совместимость схемы необходимо проверить отдельно.

Проверка: `systemctl status svoi-web svoi-bot caddy`, `journalctl -u svoi-web -u svoi-bot --since today`, внешний `/api/health`, вход через кнопку Telegram, сохранение и чтение с другого аккаунта с соответствующими правами.

## Резервные копии

Для работающей SQLite используйте её backup API или `VACUUM INTO`; простое копирование одного файла `.sqlite` при активном WAL может пропустить последние операции. Храните копии с уникальным временем в имени и проверяйте их командой `PRAGMA integrity_check`. Резервная копия содержит персональные данные и сессии, поэтому права доступа должны быть не слабее прав рабочей базы.

В комплект входит `deploy/backup.py`: стандартный Python `sqlite3.Connection.backup` создаёт согласованную копию, затем проверяет `PRAGMA integrity_check`, устанавливает права `0600` и оставляет 30 последних копий. Каталог копий принадлежит root, права `0700`.

```bash
python3 /opt/svoi/current/deploy/backup.py
systemctl status svoi-backup.timer
systemctl list-timers svoi-backup.timer
```

Ежедневный systemd-таймер настраивается при развёртывании. После установки отдельно проверьте его состояние и реально созданную копию: инструкция сама по себе не подтверждает работу расписания. Копии на этом же сервере помогают восстановиться после ошибки приложения, но не защищают от потери VPS. Для такой защиты требуется отдельное защищённое хранилище вне сервера; оно пока не подключено.
## Восстановление

Кассовые ключи в SQLite зашифрованы. Для восстановления нужен исходный `POS_MASTER_KEY` (32 случайных байта в base64) из защищённого окружения сервиса. Храните резерв ключа отдельно от копий базы. Не заменяйте его при обычном обновлении приложения; потеря ключа потребует повторного ввода доступов ко всем кассам. На сервере без ключа сохранение новых подключений недоступно. Рабочий процесс POS запускается вместе с `svoi-web` и работает только с явно включёнными подключениями. При восстановлении старой копии дополнительно сверьте кассовые чеки и начисления после её времени, прежде чем включать обмен.

1. Проверьте целостность выбранной копии и дату, предупредите о потере операций после неё. Сохраните копию текущего состояния перед заменой.
2. Остановите `svoi-web`. Бот не записывает бонусы в SQLite, но открывать приложение во время восстановления пользователи не смогут.
3. Переместите текущую базу **вместе** с существующими `-wal`/`-shm` в отдельную папку восстановления. Не оставляйте старый WAL рядом с восстановленным файлом.
4. Установите проверенную резервную копию по пути `DATABASE_PATH`, назначьте владельца `svoi:svoi`, права `0600` и доступ к каталогу `0750`.
5. Очистите таблицу сессий в восстановленной базе, чтобы не восстановить ранее отозванные сессии. Пользователи войдут повторно через Telegram.
6. Запустите `svoi-web`, проверьте health, вход, данные и права. Отдельно сверьте бонусные операции после времени выбранной копии.

Восстановление заменяет общие данные всех пользователей и требует осознанного выбора копии владельцем. Остановка приложения не останавливает тарификацию VPS.

Официальные материалы: [SQLite в Node.js](https://nodejs.org/docs/latest-v22.x/api/sqlite.html), [SQLite Online Backup](https://www.sqlite.org/backup.html), [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https).
